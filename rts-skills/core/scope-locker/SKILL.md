# Title
Scope Locker

## Purpose
Define and enforce change boundaries for safe, controlled execution.

## Use When
- Work must stay within strict file or system limits.
- Risk of accidental expansion is high.

## Inputs
- Approved objective
- Candidate files/components
- Exclusions and protected areas

## Process
1. List what may be changed.
2. List what must not be changed.
3. Mark explicitly out-of-scope work.
4. Document rationale for each boundary.
5. Define escalation path for scope conflicts.

## Output Format
- In-Scope Changes
- Protected Areas
- Explicitly Out of Scope
- Scope Conflict Rules

## Guardrails
- No edits outside approved boundaries.
- No opportunistic refactors unless approved.

## Stop Conditions
- Boundaries are explicit and actionable.
- Scope conflict handling is defined.

## Handoff Notes
Record boundary decisions and pending approvals.
