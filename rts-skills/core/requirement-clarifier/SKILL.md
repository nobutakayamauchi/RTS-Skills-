# Title
Requirement Clarifier

## Purpose
Clarify objective, constraints, acceptance criteria, non-goals, and unknowns before execution.

## Use When
- Requirements are partial, mixed, or ambiguous.
- Scope risk is high.

## Inputs
- User request
- Existing constraints
- Relevant artifacts or context

## Process
1. State the primary objective in one sentence.
2. List constraints (time, scope, quality, tooling).
3. Define acceptance criteria.
4. Identify explicit non-goals.
5. List unknowns and assumptions.
6. Confirm what must be clarified before implementation.

## Output Format
- Objective
- Constraints
- Acceptance Criteria
- Non-Goals
- Unknowns
- Assumptions
- Clarification Questions

## Guardrails
- Do not infer missing requirements silently.
- Separate facts from assumptions.

## Stop Conditions
- Objective and acceptance criteria are testable.
- Blocking unknowns are surfaced.

## Handoff Notes
Highlight unresolved questions and decisions required from requester.
