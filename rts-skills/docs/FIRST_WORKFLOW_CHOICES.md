# First Workflow Choices

## What this page helps you choose
Use this page to pick your first run between:
- Codex quickstart
- Claude quickstart
- bugfix bundle
- feature-build bundle

## Choose Codex quickstart if...
- You want a copy-paste, execution-focused starting flow.
- You prefer tight scope control and patch-oriented changes.
- You want concise reporting with clear verified vs unverified output.

**Best for:** first small edits with explicit file boundaries.

## Choose Claude quickstart if...
- You want explicit planning before execution.
- You prefer structured reasoning and phased output.
- You need assumptions and unresolved items called out clearly.

**Best for:** first runs where clarification and planning quality matter.

## Choose bugfix bundle if...
- You already have a reproducible defect.
- You want diagnose → fix → verify flow.
- You can keep the fix surface minimal.

**Best for:** targeted repairs, not net-new features.

## Choose feature-build bundle if...
- You need to deliver a small new capability.
- You want requirement clarification, decomposition, scoped implementation, and handoff.
- You have stable acceptance criteria.

**Best for:** small, scoped feature additions.

## What to avoid as your first run
- Do not start with a large, multi-area change.
- Do not start bugfix flow without a reproducible issue.
- Do not start feature-build flow when requirements are still unclear.
- Do not mix multiple bundles in your first attempt.

## Recommended first run
1. If uncertain, start with **Codex quickstart** or **Claude quickstart** based on your environment.
2. After one successful small run, choose **bugfix** for defects or **feature-build** for new scoped work.
