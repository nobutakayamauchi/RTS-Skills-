# Next Steps

## Who this page is for
This page is for users who already completed one small successful run and want to keep improving without over-scoping.

## What to do next
1. Repeat the same workflow once more on a slightly larger (but still single-area) task.
2. Keep scope explicit with `core/scope-locker` before making changes.
3. Keep reporting disciplined with `core/verification-runner` (verified, unverified, assumptions).

## Recommended second workflow
Run a **small feature-build flow** on one clear improvement:
1. `core/requirement-clarifier`
2. `core/task-decomposer`
3. `core/scope-locker`
4. `core/safe-implementer`
5. `core/verification-runner`
6. `core/handoff-writer`

## Recommended third workflow
Choose based on your next task:
- If you have a reproducible defect: use `bundles/bugfix.md`.
- If you need a scoped enhancement: use `bundles/feature-build.md`.

## What to postpone
- Large cross-repo or multi-domain changes.
- Creating new bundles before current bundles feel routine.
- Deep customization of shells before your baseline flow is stable.

## When to revisit growth and media
Revisit `growth/` and `media/` after your core engineering flow is stable across multiple runs.
Start earlier only if your immediate task is explicitly content, SEO, sales, or creative production.
